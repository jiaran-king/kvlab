# Goal：KVLab v0.3——缓存规则修正与 AgentInfer Replay 负载接入

实现一个能够导入 AgentInfer Replay 冻结负载、比较不同 KV 容量并解释结果的离线模拟器。本版本聚焦两件事：

1. 修正已经确认的缓存机制差异，建立直接对照目标源码的验证。
2. 复用 Replay 的负载构造流程，支持不同 trace 和配置生成的负载，不再依赖工整的手工请求作为正式容量分析依据。

最终交付仍为**单文件离线 HTML**。负载导出器可以是独立 Python 工具，但网页运行不依赖 Python、Node、本地服务或网络。

不启动真实模型推理，不申请 GPU/NPU，不开展新硬件实验。不以容量曲线平滑、单调上升或出现正收益作为完成标准。

## 1. 架构与职责

```text
trace + Replay 配置 / 已有完整输入 capture
                    ↓
复用 AgentInfer 的解析、采样、规划和请求构造
                    ↓
             Replay → KVLab exporter
                    ↓
             冻结 workload.json
                    ↓
        KVLab 配置路由和执行规则
                    ↓
       同一缓存核心 + 明确的执行模式
                    ↓
       容量扫描、逐请求解释、结果导出
```

- **AgentInfer 决定请求内容、身份及上下文关系。**
- **exporter 冻结这些事实并记录来源与假设。**
- **KVLab 决定这些请求经过指定缓存和执行规则后的结果。**

不得在 JavaScript 中另写一套 PromptBuilder、sampler 或 trace analyzer。保留简单合成负载用于机制测试，不继续扩展随机长度、随机竞争等参数。

## 2. 首先核对源码与输入资产

实现前形成简短资产说明，明确：

- 使用的 AgentInfer、vLLM、vllm-ascend 版本和已知本地修改。
- 当前缓存预设所依据的源码、适用路径和尚未核实的部署差异。
- trace、Replay 配置、plan、token capture、tokenizer 和请求模板的可用情况。
- 哪些输入是实际捕获，哪些依赖或内容由规则推导。
- 离线 exporter 的可行路径及缺失条件。

优先使用已有本地资产。关键证据不足时明确报告，不通过猜测补齐，不为了补齐证据自动启动模型或硬件实验。

## 3. 修正缓存回收机制

严格对齐选定源码中的：

- 空闲队列初始化。
- 引用计数增加和减少。
- 批量释放的顺序。
- 无 hash 块放到队头、有 hash 块追加到队尾的行为。
- 从队头分配及缓存索引失效的顺序。

**不得把它简化成“从未使用的新页始终优先”。** 未使用的块与已释放的块如何排序，应由目标源码的队列语义决定。

必须验证：

1. 存在无缓存空闲块时，不提前覆盖带有效缓存的空闲块。
2. 仍被活动请求或传输引用持有的块不能回收。
3. 批量释放后，分配顺序与目标源码一致。
4. 同一前缀身份可以对应多个物理块，索引与引用分别正确。
5. 只有覆盖有效缓存时，才计为缓存替换；无 hash 块复用单独统计。

先完成这一部分，再重新评价容量曲线。

## 4. 建立独立于双实现一致性的验证

直接调用或提取冻结源码中的相关逻辑，使用最小替身对象建立可执行对照。对照至少覆盖：

- 分配、批量释放和回收顺序。
- 引用与缓存索引变化。
- 窗口状态释放及 checkpoint 保留规则。
- 多缓存组共同恢复边界。
- 容量准入与实际分配的区别。

测试预期不能只来自当前模拟器。Python/JavaScript 逐字段一致可以保留，但仅作为迁移一致性检查。

若目标源码逻辑无法独立执行，明确说明原因，使用可手算案例及逐行对应的规则验证，并标注验证强度，不宣称完整等价。

## 5. Replay workload 格式

定义一个小型、明确版本的格式，例如：

```json
{
  "schema": "kvlab-replay-workload/v1",
  "metadata": {},
  "requests": []
}
```

metadata 至少包含：

- trace 来源和版本标识。
- AgentInfer、exporter 版本及相关修改说明。
- Replay 配置、采样种子。
- 模型、tokenizer、请求渲染模板身份。
- 内容来源模式、依赖推导方式及显式假设。
- 等待和时间字段的单位与语义。

来源指纹仅用于确认是否为同一份输入，避免重复比较大文件；不能将指纹当作内容正确性的证据。

每条请求至少表达：

- 唯一 runtime request、session、actor 身份。
- source key，仅用于溯源。
- 有序输入 token 身份与实际输入长度。
- 输出长度及其来源。
- `send_after`、`context_after`、`context_mode`。
- 等待条件、会话启动条件及必要的 timing-only 节点。

所有具体输入必须绑定完整 runtime 身份。重复采样同一源请求时，不能仅按 `source_key` 关联内容。

## 6. 离线内容构造与 exporter

复用 AgentInfer 的 analyzer、sampler、planner、PromptBuilder，增加薄适配层，不复制其业务逻辑。

支持两种明确区分的内容来源：

### 完整输入 capture

使用最终进入 P 的输入 token，保留必要的模板和缓存隔离信息。明确 capture 对应的具体运行实例。

### trace 驱动的合成内容

没有完整 capture 时：

- 使用确定性的输出替身，供后续请求构造使用。
- 由同一个 PromptBuilder 处理共享内容、私有内容、追加、裁剪和角色差异。
- 使用与目标请求路径一致的渲染和 tokenization。
- 标明“trace 驱动的合成内容”，不得称为历史逐 token 精确重放。

不得在 KVLab 中通过“父输入＋输出长度＋补齐片段”替代正式 Replay 请求构造。

导出器必须在离线、CPU 条件下工作。优先使用已有 capture 或本地 tokenizer 与模板。当前 Replay 的 HTTP tokenizer 依赖应通过明确的离线适配解决；不能默默启动模型服务，也不能换用不一致模板后声称等价。

若缺少必要 tokenizer、模板或 capture，交付可用部分并明确缺口，不将相关验收标为通过。

完整 token IDs 过大时，可以使用等价的共享内容表示，但必须验证其前缀身份、切片与隔离语义不变，不能只保留长度。

## 7. 区分 workload 和完整 scenario

### 导入 workload

冻结请求内容、身份、依赖和外部到达／等待条件。用户可以配置：

- KV 容量及支持的缓存布局组合。
- P 实例数和固定路由。
- 支持的执行模式与参数。

修改这些条件后生成新的场景快照。

### 导入完整 scenario

保留其中的请求、路由、执行模式、执行参数，以及固定事件模式下的事件流。只允许覆盖明确声明的实验变量，例如 KV 容量。

导入时显示请求数、会话数、actor 数、来源、内容模式、schema 和假设，避免用户误认实际运行的负载。

未知格式、原始 Replay plan 或字段缺失文件应明确拒绝并说明所需格式，禁止静默回退到默认合成负载。导入失败后清除旧导入状态，禁止继续误跑旧文件。

## 8. 两种执行模式共用一个缓存核心

### 固定事件回放

保留现有能力，用于逐事件核验和明确轨迹下的容量比较。

固定执行机会、顺序、预算和释放条件；命中、实际计算和物理分配由缓存核心重新计算。不得把历史命中或淘汰结果作为模拟输入。

### 负载驱动执行

用于 Replay 负载的主要分析：

- 冻结请求、依赖、路由、外部等待和执行规则。
- 首次获得执行机会时查找并准入缓存。
- 从实际采用的缓存边界继续计算剩余输入。
- 不再强制消费冷输入预生成的零计算占位步骤。
- 请求完成、依赖解除及后续交错可以随命中结果变化。

两种模式在输入、结果和界面中明确标注。不得悄悄改变旧冻结场景的含义。

## 9. 执行语义必须完整且确定

在接入 Replay 验收前明确以下规则：

- 会话何时启动、何时释放会话并发名额。
- 请求何时满足发送和上下文准备条件。
- 每个 P 的活动请求限制及单步计算预算。
- P 输入完成、传输引用释放、D 完成的先后关系。
- 同一虚拟时刻多个事件的确定性处理顺序。

严格区分：

- Replay 会话并发。
- 请求在途数量。
- P 侧同时处理输入的请求数。

不得直接复制同一个并发数并认为语义一致。

等待时间不能默认为零。定义并记录从 trace 等待到虚拟时间的转换、比例和取整规则；不得直接把秒与 tick 相加。

D 侧可以采用简化、确定性的完成规则，但必须记录输出长度是否影响完成时机，以及具体假设。不模拟真实 decode 吞吐、传输性能或秒级 TTFT。

空间不足时报告具体请求、事件和原因，不自动引入未定义的抢占、重算或重试策略。

## 10. 容量扫描的变量控制

一次容量扫描必须使用相同的：

- 请求集合、token 身份和运行身份。
- 依赖、外部到达和等待条件。
- 路由、执行模式及执行参数。
- 缓存规则版本和随机种子。

只改变 KV 预算及由它推导的物理容量，不在每个容量点重新采样或构造内容。

固定事件模式保持事件轨迹一致。负载驱动模式允许内部事件和完成顺序随缓存结果变化，但必须保留实际事件记录。

修改路由、布局、并发或等待规则属于另一组场景，不能混称为单纯容量扫描。

## 11. 必要诊断与解释

保留逐请求输入量、采用缓存量、实际输入计算量、恢复边界和限制组。

增加：

- workload 请求、会话、actor 数及内容来源。
- 每个 P 的首次使用块数、无 hash 块复用数、有效缓存替换数。
- 活动引用、可替换缓存及无有效内容的空闲块状态。
- 状态形成、释放、替换与后续查找之间的事件证据。

不得混淆：

1. 长度允许的边界。
2. 内容相同的前缀。
3. 已形成合法状态的复用机会。
4. 当前存活并最终采用的缓存。

不能仅凭“未命中”断言发生过淘汰。解释不足时如实显示未知或证据范围。

可在固定事件模式增加“同规则、同轨迹、无淘汰参考”，用于区分缺少复用机会与容量造成的损失；不得把不同执行顺序下的参考结果冒充严格可配对的逐请求上限。

结果必须区分输入错误、不支持、工具资源超限、固定规则下不可执行、取消及完整成功。部分执行不得汇总成完整容量点。

## 12. 必要测试与 Replay 验收

保留小型、可手算案例，覆盖：

- 普通续接与合法恢复边界。
- `A1 → B → A2` 中缓存存活与确实发生的容量淘汰。
- 无 hash 块优先回收及批量释放顺序。
- 多组状态缺失后的共同边界回退。
- 活动引用和传输引用释放。
- D 输出不会提前成为 P 缓存。
- 主 Agent 等子 Agent 完成，却继承自己旧上下文。
- 命中后直接推进剩余输入。
- 等待、会话并发、同刻事件顺序。
- 导入失败、取消和极小容量的正确处理。

Replay 验收要求：

- 核对现有案例的实际资产版本；适用时准确导出和导入 6 个会话、425 条请求。
- 固定选取 append、trim、主子 Agent 切换、重复采样案例，与 Replay 构造结果直接对照内容和依赖。
- 至少再使用另一套采样配置及一份不同的小 trace，证明未绑定固定案例。
- 相同输入与执行配置重复运行，模拟结果一致；墙钟时间等非模拟元信息另行存放。
- 容量扫描前后，冻结负载和路由不变。
- 验证导出、导入、运行、结果导出与重新运行的完整流程。

不能只检查 exporter 与 importer 互相一致，也不能只检查 token 记账守恒。

## 13. 界面与旧结果处理

保持主界面简洁：

- 简单合成负载明确定位为机制测试。
- 支持 Replay workload 和完整 scenario 导入，并说明区别。
- 425 案例作为文件和回归资产保留，**不恢复主界面专属选项**。
- 沿用已讨论的直观名称，补清路由、并发和单步预算说明。
- 结果绑定实际场景；编辑条件后显示尚未重跑。
- 保留方案删除、清空和导出功能。

修复后重跑此前竞争案例及细粒度容量扫描，保存修复前后差异和原因。旧报告保留为历史记录并标注失效或待重新验证，不继续把旧曲线作为可信容量收益证据。

浏览器交互未实际验证时明确记录，不能用脚本测试代替界面验收。

## 14. 实现顺序

1. 核对源码、Replay、capture 和 tokenizer 资产。
2. 修正回收规则，完成独立机制对照。
3. 重跑旧案例，修正相关结论。
4. 定义 workload 格式、内容来源与执行语义。
5. 实现离线 exporter 和严格 importer。
6. 核对内容、依赖、等待和身份。
7. 完成负载驱动执行，保留固定事件模式。
8. 运行小规模配对容量扫描与回归测试。
9. 完成单文件网页、CLI、文档及使用流程验证。

不得为了尽快展示容量收益，跳过前面的正确性验证。

## 15. 交付与完成标准

交付：

- 修正后的缓存核心及独立验证案例。
- 复用 AgentInfer 的离线 exporter。
- workload schema、支持范围及导入校验。
- 两种执行模式及确定性规则说明。
- 共用计算核心的单文件 HTML 和 CLI。
- 小型机制案例、Replay 文件案例及旧结果更正记录。
- 导出、导入、容量扫描和复现说明。

完成意味着：

> 在明确支持范围内，不同 AgentInfer trace 和配置可以生成冻结负载并导入 KVLab；缓存命中、恢复边界、回收和执行变化有可核对的规则与事件依据；同一负载的容量比较可复现，限制和假设清楚呈现。

不要求扩容必然受益，不要求曲线平滑，不把尚未核实的源码预设宣称为实际部署的精确预测。
