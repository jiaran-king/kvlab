# 四张 H20 的 KV 容量—性能 Benchmark：最终报告

**在可比较的 12 GiB（L）与 48 GiB（H2）两次运行中，P 本地命中率增加 2.73 个百分点，本地输入计算计数减少 26.79%；后续轮 TTFT P95 从 5.229 降至 3.949 秒，P50 从 0.662 增至 0.699 秒。** 这是单次闭环工程观察，不能解释为已证明稳定的容量因果收益。

本阶段新增两次完整回放，总预算四次已用完。48 GiB 复核成功；24 GiB 出现一次 KV 就绪等待／客户端读取超时，导致 13 条依赖请求跳过。因此交付的是**有效的 12/48 GiB 端点对照、旧 H 历史观察和 24 GiB 失败测量**，没有取得三个完整可比较容量点。不能由此判定拐点、饱和区或边际递减，不追加实验。

## 可以支持什么结论

L→H2 本地命中增加 190,464 token，即 **2.7296 个百分点**；本地输入计算计数减少 190,464，即 **26.7884%**。H2 与旧 H 的命中、输入计算计数完全相同，但它们的延迟差异很大，说明不能把缓存计数收益直接换算成 TTFT 收益。

按 `(低容量−高容量)/低容量`，L→H2 后续 TTFT P95 改善 **24.4831%（减少 1.280 秒）**，P50 改善 **−5.5367%（增加 0.0367 秒）**。E2E 两个分位数变化较小；回放任务窗口缩短约 1.43%。这些是观测差值，没有多次独立重复来验证稳定性。174 条请求不是 174 次独立系统实验，闭环完成速率也不是最大服务吞吐。

当前证据支持 12–48 GiB 端点之间存在本地复用差异；没有有效中间点，不能比较 12→24 与 24→48 的边际收益。没有依据认定最优容量、缓存饱和或主要瓶颈位于缓存之外。

## 旧 H 审查与 H2 选择依据

H/L 原始完整性审查通过，配置差异仅 P 预算。进一步读取 H 日志发现 42 组配对的 TileLang 编译起止记录，两个 TP rank 各 21 组；L 无同类区间。H 最慢 10 条后续请求的发送至首 token 区间均与至少一组编译区间重叠。

这是实际编译活动的证据，不能证明全部尾延迟均由编译造成。388 rank-seconds 合计包含重叠，不是墙钟开销，不从 TTFT 中扣除。日志按内嵌时间对齐，客户端 UTC、服务 UTC+8，编译记录精度为秒；缓冲输出的行顺序不代表事件顺序。尾部对齐表同时包含 L 自己的尾部、同 trace ID 对照、session/actor/轮次/长度和客户端在途数；在途数不冒称服务队列。

H2 沿用两条预热、清空 P 前缀及原计时协议，使用已经历 H/L 的现有磁盘编译缓存，没有增加预热形状。H2 无正式窗口 TileLang 编译开始记录，但 P 仍有两条 JIT 监测告警，不能宣称完全没有编译。L、H、H2、M 的 P 都有两条此类告警，告警数不能替代实际编译区间数。

在 H2 运行前已写明：若同类编译现象未复现且其他条件一致，则 L/H2 作为准备状态更接近的单次工程对照，再测 M；旧 H 保留。选择依据见 [DECISION.md](DECISION.md)，不是从多次运行中挑最快值。H2 的 P50 实际比旧 H 略慢，也照实呈现。

## 24 GiB 的失败及证据边界

原 trace 请求 `5c7c6017-db96-4e9c-9b85-516c206fa824`，session `66fd0455-0715-4b7b-ab93-d2aeb4323268` 的一个 subagent 第 4 轮，计划输入 28,577、输出 89 token。运行请求 ID 为 `bc545f2b-f725-57d5-b0df-f53d2716ec44`，在 UTC 17:41:28 发出，17:56:28 以 `ReadTimeout` 结束，耗时 900.034 秒。HTTP 状态曾为 200，但未取得有效首 token 和最终 token 计数。

D 的两个 TP worker 在 UTC+8 01:49:28 对同一个内部请求 ID `chatcmpl-0a60d905-3a63-4198-966a-0e2fa6e83c4e-b6439228` 记录 `Timeout waiting for P side ready`。这是两条 rank 日志，不是两次独立请求失败；内部 ID 与客户端 ID 不同，本报告保留两者，不伪造逐跳关联。最终 Replay 记录一个任务失败、两个完成，13 条请求为 `skipped_dependency_failed`。没有定位为何未收到 P 就绪，不据此认定 24 GiB 放不下或容量必然导致传输失败。

P 的周期传输汇总中没有非零错误，而 D 的直接错误日志明确存在，说明不能仅用 P 汇总断言链路无错误。H/L/H2 未见同类 D 错误。新统计同时保留周期汇总计数与直接 KV 错误 rank 记录；D 无独立周期汇总记为缺失。

M 在正式窗口无 TileLang 编译开始记录，但失败及其等待改变了闭环进度和实际覆盖，缓存和延迟均不能作为完整中间点。依预算不重跑、不修改超时和负载、不补第五次，也不删除异常请求后重算“完整”结果。

## 固定条件和复现口径

同节点 `vllm-h20-01`，四张 H20-3e，每卡 150,110,011,392 字节；P TP2＋D TP2，即1P1D。D 固定48 GiB／卡。模型目录 `/home/david_cwq/jinghaoyu/models/DeepSeek-V4-Flash`，vLLM 0.26.0、原 Mooncake RDMA 依赖及 patch，加载日志量化为 `deepseek_v4_fp8`、基础 bfloat16、FP8 KV。使用 eager、上下文81920、MBT8192、P max_num_seqs=2、D=4，P APC开、D APC关，无投机解码、AFD、额外offload或D→P回读。

H2/M 与 L 的 Replay 配置除输出目录外相同，计划完全一致；D 命令相同，P 命令仅 KV 字节数变化。相关执行脚本和已有客户端 patch 已核对，见 source-comparison.json。未重新散列大权重，也没有把目录名冒称已验证的远端 checkpoint revision。

GPU物理UUID未固定：L/M使用同一组，H2由SLURM分配到同节点另一组同型号卡。共享主机背景负载不恒定；M结束前约3分24秒，另两个Qwen作业开始运行，晚于D超时日志和客户端超时，不能倒因为超时原因。设备与背景变化是性能归因限制，不声称严格隔离的纯容量因果实验。

负载来自 AgentInfer commit `7f304555a8bc504c2c2257db2662e896eeeb5c30` 的 `tests/agentbench/replay/claude_trace_8session_requests.jsonl`，保留原三个完整session：`66fd0455-0715-4b7b-ab93-d2aeb4323268`（65条）、`c4d23e13-7f6c-4998-af37-d6a3e8b4067f`（75条）、`7aefcc2d-844d-4445-b575-350f065a0a52`（34条）。并发3、seed0、同actor等待缩放0.1、adaptive与`claude_code_minimal_v1`，原输出长度不变。这是synthetic Trace Replay，不执行真实工具，也不是原生产文本和时序的完整重现。没有完整prompt/token记录，无法证明token级前缀等价；长度和ID一致不等于内容相同。

每次两条预热后等待完成，P reset均HTTP200且success:true，再取正式起始metrics；结束时取终止metrics。counter保留role与engine标签，不累加TP重复序列；local hit/query和`prompt_tokens_by_source_total{source="local_compute"}`各用自身口径。输入来源计数不等于FLOPs、GPU时间或所有物理重算，不把全量计数分摊给后续请求。

TTFT使用客户端请求开始至首个有效生成内容，不计人为等待或空流事件；按上下文续接及实际reset划分，均无实际reset。分位数为线性插值。E2E为客户端成功请求latency；任务窗口从首任务入队到最后任务终止，HTTP窗口及manifest窗口另列于CSV。容量采用运行时预算与block数，未核算逐tensor精确物理字节。worker与scheduler的token容量口径不同，不混用或乘以TP数，见原 evidence/capacity-interpretation.md。
